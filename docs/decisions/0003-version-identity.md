# 0003: Versions are identified by UUID, not by snapshot name

**Status:** Accepted

The naming convention `VM_NAME_YYYYMMDDhhmm` has one-minute resolution, and several agents can create
snapshots at once, so two different snapshots can share a name.

Every version therefore has a random UUID as its identity, generated by whoever creates it. The snapshot
name is a non-unique label, and archive keys are derived from the UUID. Parent references, agent state
and sessions all use the UUID.

Random UUIDs (v4) are used because the standard libraries provide them. The database's native `UUID` type
stores them compactly, and the volume of versions is too low for index fragmentation to matter. If it
ever does, UUIDv7 can be adopted without a schema change.

Considered and rejected: appending a counter to same-minute names, which breaks the requested format and
would need coordination between agents.
